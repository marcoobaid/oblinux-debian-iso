## Scope limitations

This test does not validate UEFI installation, encryption, manual partitioning,
dual boot, Secure Boot, physical hardware, upgrades, or interrupted-install
recovery.

## Findings

### UEFI was not enabled

The original test plan assumed a UEFI VM, but the evidence proves VirtualBox
used legacy BIOS. Future UEFI tests must enable EFI in the VM's System settings
before booting the ISO. The disk layout must contain a FAT EFI System Partition,
and `test -d /sys/firmware/efi` must succeed in both live and installed systems.

### Debian settings control final APT sources

The installed sources contain `main` and `non-free-firmware`, including Trixie,
updates, security, and backports. They do not contain `contrib` or `non-free`,
even though the live-image build permits those archive areas.

This is not a Calamares failure. Debian's `sources-final` helper deliberately
writes that policy. OBLinux must provide its own helper or settings package
before its final repository policy can differ.

### Automatic time synchronization is absent

The clock was not synchronized and no NTP service was available. The Build 002
manifest contains neither `systemd-timesyncd`, Chrony, nor NTPsec. A daily-driver
image requires an explicit time-synchronization package and service policy.

## Repeatability gate

Repeat the procedure with the same ISO and a newly created blank virtual disk,
this time with EFI explicitly enabled. Build 002 completes its installer gate
only after two UEFI installations and post-install update checks pass.
