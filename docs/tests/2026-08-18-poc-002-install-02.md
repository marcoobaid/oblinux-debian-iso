## Finding: live-session lock during installation

The GNOME live session automatically locked while Calamares was unattended.
Although the documented Debian live password restored access and installation
completed, requiring a password during installation is a poor and potentially
confusing user experience.

A later OBLinux image must disable automatic screen locking and automatic
suspend for the live account. The installed user's normal power and privacy
defaults must remain unaffected.

## Resolved finding: perceived four-to-five-minute boot

The installation initially appeared to spend approximately four to five minutes
between GRUB/initramfs startup and the GDM login screen. Repeated boots were fast
when the VirtualBox window was not resized or maximized during startup.

Collected evidence disproves an operating-system boot delay:

- Kernel startup: 3.488 seconds
- Userspace startup: 4.654 seconds
- Total measured startup: 8.143 seconds
- Graphical target reached after 4.653 seconds of userspace startup
- GDM service startup: 86 milliseconds
- Longest critical-path unit: `plymouth-quit-wait.service` at 2.546 seconds

No filesystem, swap, network, firmware, or service timeout delayed
`graphical.target`. The perceived delay is classified as a VirtualBox
display-refresh or resize artifact involving the `vboxvideo` path, not an
OBLinux boot-performance defect.

The journal contains a later 120-second GNOME keyring/portal activation timeout
inside the GDM session. It occurs after GDM and the graphical target are active,
is not on the boot critical path, and did not prevent login. It should be
monitored only if it produces a separate user-visible symptom.

For this VM configuration, avoid resizing or maximizing the VirtualBox window
during early boot. This testing workaround does not imply a physical-hardware
problem.

## Verified UEFI layout

The diagnostic collection confirms:

- The installed system booted in UEFI mode.
- A 300 MiB FAT32 EFI System Partition is mounted at `/boot/efi`.
- A 31.3 GiB ext4 root filesystem is mounted at `/`.
- An 8.4 GiB swap partition is active.
- `/etc/fstab` uses matching UUIDs for EFI, root, and swap.
- The kernel resume UUID matches the swap partition.

`findmnt --verify` reported no parse errors. Its three filesystem-detection
warnings resulted from the unprivileged command lacking block-device inspection
permission and do not indicate invalid mounts.

## Verified installed system

Post-install evidence confirmed:

- The firmware boot order selects a `Debian` entry that loads
  `\EFI\Debian\shimx64.efi` from the installed EFI System Partition.
- The created user belongs to `sudo` and the expected desktop and device-access
  groups.
- Administrative authentication through `sudo` succeeded.
- The selected hostname was applied.
- Locale is `en_US.UTF-8`, keyboard layout is US, and timezone is
  `America/Chicago`.
- No packages matching `live-*` or `calamares*` remain installed.
- No live-media APT source remains.
- APT successfully refreshed Trixie, updates, security, and backports metadata.
- The installed system reported no pending package upgrades.

The final APT sources use `main` and `non-free-firmware`. This matches Debian's
packaged Calamares helper but not yet OBLinux's proposed inclusion of `contrib`
and `non-free`; that policy remains Build 003 work.

Automatic time synchronization remains absent: the system reports no NTP
service and an unsynchronized clock. This is a known image-composition issue,
not an installer failure.
