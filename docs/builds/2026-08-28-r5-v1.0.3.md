# R5 v1.0.3 FastFetch integration

This change adopts the immutable OBLinux Brand Master v1.0.3 release and
switches Debian's new-user FastFetch default from the legacy downstream OB
artwork to the package-owned shared R5 terminal identity.

- Release: `v1.0.3`
- Annotated tag object: `69769044fb015e9818dd72e7c32a68c3fc92c09f`
- Commit: `46e3ed6986d3785c28639bd2dd6656203e2758c7`

The tag and peeled commit were verified against the authoritative GitHub

manifest places the shared FastFetch files at:

- `/usr/share/oblinux/terminal/fastfetch/logo.txt`
- `/usr/share/oblinux/terminal/fastfetch/config.jsonc`
- `/usr/share/doc/oblinux-branding/fastfetch/README.md`

## Downstream integration

The Debian new-user configuration under `/etc/skel` references the
package-owned logo directly and retains the existing Debian-specific package
count module. The legacy `/etc/skel/.config/fastfetch/oblinux.txt` artwork is
removed. Existing users' home directories are not modified; their personal
FastFetch configuration remains under their control.

Debian 13's FastFetch 2.40.4 rejects `#RRGGBB` color strings. The downstream
configuration therefore expresses the unchanged canonical colors with the
supported ANSI true-color forms `38;2;30;77;140` and `38;2;255;138;0`.

The existing Zsh startup policy remains unchanged: FastFetch runs once for a
top-level interactive terminal and can be disabled with
`OBLINUX_FASTFETCH=0`.

## Verification boundary

The following checks passed in the macOS development workspace:

- authoritative tag object and peeled release commit verification
- immutable commit-archive SHA-256 verification
- upstream package version and exact FastFetch install-path inspection
- `scripts/validate-branding-integration`
- shell syntax checks included in the integration validator
- repository diff whitespace validation

This workspace does not provide Debian `live-build`, Debian package build
tools, or FastFetch. Consequently, the `oblinux-branding` package build, full
ISO build, ISO payload inspection, and actual terminal rendering were not run
here. They remain required on the Debian 13 amd64 build host, followed by the
manual checks in `docs/tests/BRAND_MASTER_RUNTIME_TEST.md` and
`docs/tests/TERMINAL_EXPERIENCE_ISO_TEST.md`. Previously accepted R5 surfaces
were not redesigned by this integration, but must still receive regression
confirmation on the resulting ISO.
