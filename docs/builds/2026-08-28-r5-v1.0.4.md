# R5 v1.0.4 FastFetch integration

> **Superseded artifact warning:** the ISO and checksum recorded in the original
> build section below contain unactivated Calamares package defaults because a
> retained chroot skipped the downstream branding hook. They remain valid only
> as FastFetch acceptance evidence. Do not distribute or promote that ISO. See
> [Issue 0006](../issues/0006-calamares-welcome-lockup-stale-chroot.md) and the
> Calamares remediation build record.

This build adopts the immutable OBLinux Brand Master v1.0.4 release to replace
the coarse v1.0.3 FastFetch artwork with the higher-fidelity shared 30×15 R5
quadrant-block logo. Debian's package-owned integration architecture, package
count, shell activation, and user-configuration boundary remain unchanged.

count module, and contains no downstream `oblinux.txt` artwork. Brand Master
v1.0.4 now ships the same FastFetch 2.40.4-compatible ANSI truecolor forms that
were previously verified downstream: `38;2;30;77;140` and

The first build invocation upgraded the retained chroot to `1.0.4-1` but
live-build reused its completed binary stage. That invocation was not accepted
as a new ISO. The stale binary stage was removed with `lb clean --binary`, and
the successful build above created a fresh SquashFS and ISO from the updated
chroot. The ignored checksum sidecar was then regenerated from the new ISO.

Read-only inspection of the ISO's embedded SquashFS confirmed:

- `oblinux-branding` `1.0.4-1` is installed;
- the package-owned logo has 15 rows and SHA-256
  `a0d28b2b48ec680768694cacb8707d77c79b3bf8102094f686c76ea739642696`;
- both package-owned FastFetch files are present under
  `/usr/share/oblinux/terminal/fastfetch/`;
- the new-user config references the package-owned logo and retains Packages;
- blue/orange ANSI truecolor values remain intact; and
- `/etc/skel/.config/fastfetch/oblinux.txt` is absent.

FastFetch executed successfully inside the completed chroot using version
2.40.4. Both text and JSON modes accepted the configuration, the package-owned
logo loaded, and the JSON result retained the Packages module. This is a
functional chroot check, not GNOME/Ptyxis visual acceptance.

## FastFetch visual acceptance

Status: **PASS — approved.**

The generated Debian 13 development ISO passed visual testing in a
GNOME/Ptyxis VM environment, and the Brand Master v1.0.4 FastFetch presentation
was approved. The review confirmed:

- the v1.0.4 R5 terminal logo renders correctly;
- the new 30×15 representation is substantially more faithful to the approved
  R5 identity than the previous v1.0.3 20×10 implementation;
- the blue outer geometry is recognizable and appropriately proportioned;
- the orange internal geometry is recognizable and no longer reads primarily
  as a generic blocky B;
- negative-space relationships are materially improved;
- the approved blue and orange colors render correctly;
- the logo size is appropriate relative to the FastFetch system-information
  block;
- FastFetch system information remains readable;
- Debian package-count output remains present; and
- no legacy OB FastFetch artwork is visible.
