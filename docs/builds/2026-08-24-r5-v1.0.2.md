# R5 v1.0.2 integration build

This build adopts the immutable OBLinux Brand Master v1.0.2 release.

## Source provenance

- Release: `v1.0.2`
- Commit: `c68c76d3847714ac66f0e3ebea1fc61984dd556d`
- Commit archive SHA-256:
  `d6fe90702787ce13e9eb67883dd6e2488f269af2a888a875fcc096f27e93e5f5`
- Debian package: `oblinux-branding` `1.0.2-1`

The published annotated tag resolves to the pinned commit. The package adds a
dedicated padded GNOME About asset and replaces the shared Plymouth payload
with a two-times-size symbol and dots plus a counter-driven orange active dot.

## Downstream integration

The scalable `vendor-logos` alternative now selects the generated
`/usr/share/oblinux/branding/oblinux-about-gnome.svg` presentation wrapper,
derived from the package-owned `/usr/share/oblinux/vendor/oblinux-about.svg`.
Other hicolor icons and vendor-logo variants retain their existing
package-owned assets. Plymouth remains an unmodified Brand Master theme
selected through the existing Debian activation hook and copied into initramfs
by `update-initramfs`.

Runtime testing confirmed the Plymouth correction, but also showed that the
v1.0.2 About asset expanded far beyond the intended size. Comparison with the
accepted stable implementation established that Debian's compiled vendor
emblem requires explicit intrinsic SVG dimensions. Runtime calibration selected
256 by 256, twice the accepted stable baseline. The final integration generates
that metadata wrapper from the padded package asset and
retains `LOGO=oblinux-logo` for normal hicolor consumers.

## Verification boundary

The following checks passed on the Debian 13 amd64 build host:

- Brand Master package validation: 24 required assets and 40 SVGs
- `scripts/validate-branding-integration`
- `lb config`
- `lb config --validate`
- clean `sudo lb build`
- built package metadata: `oblinux-branding` `1.0.2-1`
- chroot alternative target:
  `/usr/share/oblinux/branding/oblinux-about-gnome.svg`
- the generated vendor wrapper declares `width="256" height="256"` and retains
  the Brand Master `viewBox="0 0 1536 1536"`
- both `os-release` files retain `LOGO=oblinux-logo`
- Plymouth rasters: 384 by 384 symbol and two 24 by 24 dot images
- animation-script assertion for the five-position refresh counter
- initramfs listing for the v1.0.2 script, symbol, active dot, and inactive dot

Artifact: `oblinux-debian-gnome-amd64.hybrid.iso`

SHA-256: `ca757eed390153e87d60407702b5f2b894809c9044e3d85d4839b3891c40f7c6`

The first clean attempt correctly stopped at a stale downstream assertion for
the v1.0.1 time-based animation expression. The assertion was updated to check
the v1.0.2 counter implementation and exact raster dimensions, and the final
artifact was produced by a new clean build rather than reusing the failed
chroot.

Runtime testing confirmed that the corrected Plymouth symbol, dots, and
animation work. A quick runtime test of this final artifact also confirmed that
GNOME About renders the 256-by-256 symbol at the approved size; extended testing
remains in progress.
